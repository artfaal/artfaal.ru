**Дата:** 2026-07-17
**Статус:** на ревью у Макса
**Автор:** Claude (брейншторм + консилиум)

---

## 1. Цель

Сейчас `artfaal.ru` = личная страница («жизнь»), `artfaal.ru/cv/` = резюме. Надо наоборот:
CV на корне, «жизнь» на `/life/`, в nav «работа» первой.

**Зачем (из брейншторма):** сайт переосмысляется. Раньше был «личная страница с CV в довесок»,
теперь CV — визитка, «жизнь» — для тех, кто копнёт глубже. Аудитория смешанная: рекрутеры + коллеги.

**Критерий приёмки:** незнакомый человек, открывший `artfaal.ru`, видит резюме; ссылки, которые
уже разосланы, никуда не ломаются; `/cv/` не отдаёт 404; тесты и pre-commit зелёные.

## 3. Консилиум

Советники: `architect`, `frontend`, `security`. Все read-only.

### 3.1 Углы

**architect** — instant (0 сек) meta refresh Google трактует как permanent redirect, это
документированный ответ, а не костыль (`jekyll-redirect-from` генерирует ровно такой файл).
Скрипт-свап хуже `git mv`: файлы различаются не тегом скрипта, а `og:type`, набором шрифтов,
title, description, canonical/og:url/hreflang. `content.js` правок **не требует вообще** —
все URL там внешние или абсолютные.

**frontend** — премиса задачи была неверна: **hero общий для обеих страниц** (`content.js:42`),
«сухого CV-тона» не существует. На `/cv/` уже сейчас тот же терминал, печатающий `cat ~/human.md`.
Терять при переезде нечего. Nav не завязан на порядок (`nth-child` только у `.tdot`/`.stagger`/`.human-card`).

**security** — trust boundary отсутствует: нет бэкенда, форм, auth, user input. XSS требует,
чтобы Макс атаковал сам себя. Риски здесь операционные, не security. JSON-LD через `textContent`
безопасен (DOM не парсит HTML заново). Не ставить `Disallow: /cv/` — краулер не увидит редирект.

### 3.2 Конфликты и вердикты

**Конфликт 1 — history-семантика meta refresh.**
`security`: «`content=0` не создаёт history-запись, JS не нужен». `architect`: «создаёт, и тогда
Back с `/` кидает на `/cv/`, который рефрешит обратно — пользователь заперт».

> **Вердикт: берём оба механизма** — `location.replace('/')` первым, `meta refresh` следом.
> По безопасности разницы нет (подтвердил security), спор про history, где браузеры расходятся.
> `replace()` гарантирует чистую историю там, где есть JS; meta refresh страхует краулеров и no-JS.
> Цели совпадают, конфликта в поведении нет.

**Конфликт 2 — судьба `/cv/`: стаб vs 404.**
Макс сказал, что внешних ссылок на `/cv/` нет → формально можно удалить.

> **Вердикт: стаб.** Аргумент не SEO (equity ≈ 0), а UX: `/cv/` в поисковой выдаче и в ATS
> рекрутеров. 404 получит **именно та аудитория, ради которой затевался переезд**. 8 строк страховки.

**Конфликт 3 — Cloudflare Redirect Rule 301.**

> **Вердикт: технически невозможен, вариант снят.** Проверено снаружи: `dig artfaal.ru A` →
> `185.199.108-111.153` (GitHub Pages напрямую), `curl -sI` → `server: GitHub.com`, `cf-ray` отсутствует.
> **Домен не проксируется** — Cloudflare здесь только DNS. Redirect Rules применяются лишь к
> проксируемому трафику. Включать оранжевую тучку ради одного редиректа = менять TLS/кэш/трафик-путь;
> вне scope. Заодно снимается спор про дрифт конфига вне репы — его просто нет.

## 4. Решение

### 4.1 Переезд — через `git mv`, не через свап скриптов

```
mkdir life
git mv index.html life/index.html
git mv cv/index.html index.html
```

`git mv` бесплатно переносит `og:type`, список шрифтов, title, description. Ручной свап требовал бы
править всё это в обоих файлах и давал шанс забыть `og:type` и Caveat.

Правим после переезда только:
- префиксы путей к ассетам (`src/` ↔ `../src/`);
- 3 URL на файл: `canonical`, `og:url`, `hreflang`.

**`page-personal.js` НЕ переименовываем.** URL — не идентичность кода. Плюс HTML кэшируется на
10 минут: устаревший корень тянет `page-personal.js?v=<старый>`; файл на месте → рендерит корректно.
Переименуем → 404 на скрипт. Ноль выгоды, ненулевой риск.

### 4.2 Стаб `/cv/index.html`

```html
<!doctype html><html lang="ru"><head><meta charset="utf-8">
<title>CV → artfaal.ru</title>
<!-- Стаб переезда /cv/ → / (2026-07). Instant meta refresh = permanent redirect для Google.
     Удалить, когда GSC покажет, что /cv/ выпал из индекса (~6-12 мес). -->
<script>location.replace('/')</script>
<meta http-equiv="refresh" content="0; url=https://artfaal.ru/">
<link rel="canonical" href="https://artfaal.ru/">
</head><body><a href="https://artfaal.ru/">artfaal.ru</a></body></html>
```

- `noindex` **не ставить** — заблокирует консолидацию сигналов.
- `/cv/` **убрать из sitemap** — редиректам там не место.
- `priority`/`changefreq` Google игнорирует официально — на цифры 1.0/0.9 время не тратим.

### 4.3 Анти-дрифт (условие того, что переезд не развалится)

**`pre-commit`** — сейчас хардкодит `for html in index.html cv/index.html` (:34) и
`git add index.html cv/index.html` (:38). Без правки `life/index.html` **никогда не получит `?v=`**
→ вечный кэш (грабля прямо из CLAUDE.md).

```sh
for html in $(git ls-files '*index.html'); do ...
```
Одна правка, больше не дрифтует. Для стаба sed — no-op (в нём нет `src/`-ссылок), безвредно.

**`test.js`** — три хардкод-списка (:246-247, :301, :471) схлопываются в одну таблицу:

```js
const HOST = 'https://' + fs.readFileSync(path.join(ROOT,'CNAME'),'utf8').trim();
const PAGES = { 'index.html': '/', 'cv/index.html': '/cv/' };   // коммит 1: текущие пути
// коммит 2 меняет таблицу на: { 'index.html': '/', 'life/index.html': '/life/' }
```

**Важно:** коммит 1 заводит таблицу с **текущими** путями — иначе тесты сошлются на ещё не
существующий `life/index.html`, упадут, и pre-commit заблокирует сам коммит 1. Переезд меняет
**одну строку таблицы** — в этом и смысл: после схлопывания хардкодов новые пути прописываются
в одном месте, а не в четырёх.

→ per-file assert `canonical === og:url === hreflang === HOST + path`;
→ assert множество `<loc>` в sitemap === `Object.values(PAGES)`.

Это ловит **настоящего убийцу**: обе страницы с canonical `https://artfaal.ru/` → Google молча
выкидывает `/life/`. Ни 404, ни ошибки в консоли, ни визуальной разницы. Ровно тот класс дрифта,
ради которого принцип и написан. Стаб `/cv/` в `PAGES` не входит — он не страница, а редирект;
на него отдельный assert (есть refresh + canonical).

**`shared.js:28`** — `const url = base + location.pathname;` вместо `base + (isCV ? '/cv/' : '/')`.
Одна строка, дрифтовать нечему. Безопасно: `shared.js` только браузерный (`test.js` читает его как
текст для dead-code, `generate-cv.js` строит свой HTML и `updateMeta` не зовёт).

### 4.4 Nav

`shared.js:127-130` — поменять порядок двух `<a>` **и тернарники** `isPersonal ? 'is-on'`.
Забыть тернарник = подсветка инвертируется **молча**, тестов на nav нет. Обновить комментарий
`components.css:1197`, который явно называет порядок «нав (жизнь|работа) слева».

### 4.5 Hero — `prompt_lines` по страницам

Корень: `["whoami", "cat ~/cv.md"]`. `/life/`: `["whoami", "cat ~/human.md"]`.
Одно поле в `content.js` (ru + en), ноль вёрстки. Поправить `test.js:48` (ждёт один массив ≥2).

## 5. Scope — 4 коммита

CLAUDE.md: «одна фича — один коммит».

1. **`refactor: пути страниц и кэш-бастинг из единого источника`** — анти-дрифт в `test.js` + хуке,
   на **текущих** путях. Идёт первым и является страховкой переезда: после него смена пути — это
   правка одной строки таблицы, а не охота за хардкодами по четырём файлам. Проверяемо само по себе:
   тесты зелёные до и после, поведение не меняется.
2. **`content: CV переезжает на корень, личная страница на /life/`** — `git mv`, головы HTML,
   стаб `/cv/`, nav, sitemap, `prompt_lines`, `shared.js:28`.
3. **`fix: og-теги заполнены статикой — превью ссылки больше не пустое`**.
4. **`fix: hero уважает prefers-reduced-motion`**.

### Коммит 3 — почему он тут

`og:title`/`og:description`/`og:image` в отдаваемом HTML = `content=""`, заполняет только JS.
**Telegram/Slack/WhatsApp/LinkedIn JS не исполняют** → единственная ссылка, которую Макс шарит,
уже сейчас разворачивается пустой карточкой. Google JS рендерит, так что *поиск* цел, а *шеринг* — нет.
Переезд делает корень рекрутерской дверью → цена бага растёт. Лечится статикой + assert
`og:title === content.js title_cv` (та же схема, что canonical).

### Коммит 4 — почему он тут

`base.css:40-43` глушит только CSS `animation/transition-duration`. Hero-анимация — `setInterval`/
`setTimeout`, она медиа-фичу игнорирует. Пользователь с reduced-motion всё равно смотрит ~6 секунд,
а скринридер ~4 секунды читает **пустой** заголовок (`revealGlitch` делает `textContent = ''`).
`window.matchMedia('(prefers-reduced-motion: reduce)')` → отрисовать hero сразу. A11y-базу не срезаем.

## 6. Что НЕ делаем

- **`content.js` не трогаем** (кроме `prompt_lines`) — внутренних URL там нет ни одного.
- **404.html** — переезд новых 404 не создаёт. Косметический пробел, не подшивать сюда.
- **Английский CV непроиндексируем** — тот же URL, язык через `localStorage`. Для рекрутерской двери
  это дыра глубже, чем `/cv/` когда-либо была. Отдельная фича (`/en/` или `?lang=en`), не в этот scope.
- **SPA-роутер через 404.html** — ловушка: GH Pages отдаёт `404.html` **со статусом 404** → краулер
  видит 404 на `/life/` → выпадение из индекса. Ровно то, что просили не продолбать.
- **`og:image`** остаётся личным фото (`shared.js:33`) на обеих страницах. Вопрос вкуса к Максу, не баг.
- **Cloudflare** не трогаем вообще (proxy выключен, см. 3.2).

## 8. Риски

1. **Молчаливая инверсия `is-on`** — тестов на nav нет, проедет мимо pre-commit. → Глазами в браузере.
2. **Забытый префикс `src/` → `../src/`** — `test.js` cache-bust regex `(?:\.\.\/)?src\/` depth-agnostic,
   **тест НЕ поймает**. Страница отрендерится пустой (весь контент — JS в пустой `<main>`). Громко в
   браузере, тихо в тестах. → Открыть обе страницы руками.
3. **Оба canonical на `/`** → Google молча выкидывает `/life/`. → Ловится новым assert (4.3).
4. **git rename detection** может спарить файлы наперекрёст (оба HTML ~90% похожи). → Ревьюить итоговые
   файлы, а не стрелки в diff.
5. **Body пустой без JS** — часть ATS/скрейперов не отрендерит. Регрессии нет (так уже), но корень
   теперь рекрутерский. Не чиним здесь, план должен знать.
