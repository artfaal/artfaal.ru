# EN-версия становится индексируемой: /en/ и /en/life/

**Дата:** 2026-07-17
**Статус:** на ревью у Макса
**Автор:** Claude (брейншторм + консилиум)
**База:** master `ce1cf9a` (после мержа 404-страницы — конфликтов нет, зона свободна)

---

## 1. Цель

Сейчас язык переключается через localStorage на том же URL → английского контента
для Google не существует, он непроиндексируем в принципе. hreflang — один
self-referencing alternate (no-op: для работы нужны минимум два взаимных).
Корень — дверь для рекрутера, и это SEO-дыра глубже, чем старый `/cv/`.

**Критерий приёмки:** `/en/` и `/en/life/` существуют как отдельные URL со
статическими EN-головами и взаимным hreflang; язык выводится из URL, localStorage
не участвует; nav внутри EN не выкидывает в RU; тесты и pre-commit зелёные;
переключатель языка работает в обе стороны на обеих страницах.

---

## 2. Что установлено в брейншторме

| Вопрос | Ответ Макса |
|---|---|
| Зачем EN | EN-рекрутеры должны находить CV через поиск — полноценная индексируемая версия |
| URL-схема | Подпапка `/en/` (не `?lang=`, не поддомен) |
| Scope | Обе страницы: `/en/` (CV) и `/en/life/` |
| Язык и localStorage | Язык = URL. localStorage выпилить, `setLang()` умирает, переключатель — обычные `<a>` |
| Голый корень | Остаётся RU. Без авто-редиректов и баннеров по `navigator.language` |
| Как строим | «Тонкие головы»: статическая EN-голова, тело рендерит JS из `CONTENT.en` (как RU сегодня) |

Советники: `architect`, `frontend`, `test`. Все read-only. `security` не звали —

### 3.1 Углы

**architect** — hreflang-кластеры взаимные и байт-идентичные внутри пары, только в
`<head>`; self-canonical на каждом URL — cross-language canonical (`/en/`→`/`) =
фатальная ошибка №1 в i18n-SEO, Google выкинет EN как дубль. Статический
`<html lang="en">` обязателен (краулеру нужна статика, не JS-рантайм). `/en/cv/`
не заводить: у EN никогда не было URL-идентичности → нет legacy → нет стаба.
JSON-LD уже язык-зависим (`CONTENT[lang]` + `location.pathname`) — правок ноль.
`CONTENT.en` уже несёт латинскую идентичность (имя, роль) — EN-головы получат
корректную личность без правок контента.

**frontend** — вся сетка 2×2 (страница × язык) должна жить в одной чистой функции,
иначе четыре хардкодных URL в `renderNav` разъедутся молча. Бренд `tb-brand` ведёт
на корень ТЕКУЩЕГО языка: языка нет в storage, единственный переносчик языка между
кликами — URL, бренд-на-`/` = молчаливый сброс EN. Кэш-рассинхрон `setLang`
невозможен: nav рисует JS, приколоченный `?v=` к своему HTML — старый HTML тянет
старый shared.js, внутренне консистентно. Миграция localStorage не нужна: авто-honor
стухшего `lang=en` вернул бы ровно выпиливаемый анти-паттерн (EN-тело на RU-URL
под RU-canonical).

**test** — PAGES → таблица объектов, всё деривируется из неё; парный URL не хранить,
а вычислять (`altOf`) — нельзя опечатать то, чего нет. Cache-bust regex теста слеп
на глубине 2 (`(?:\.\.\/)?` — ноль-или-один `../`): `/en/life/` мог бы уехать без
`?v=` и с битыми путями при зелёном тесте. Nav-тест полагается на «язык — это
`<button>`»; станут `<a>` — парсер вкладок поедет. `getLang()` обязан матчить и
`/en/`, и `/en/index.html` (прямой заход на GH Pages). `prompt_lines` не покрыт
parity-тестом: отсутствие ключа в EN = краш страницы (`.map` по undefined).

### 3.2 Конфликты и вердикты

**Конфликт 1 — x-default: ставить или опустить.**
`test`: «опционален». `architect`: «ставить, на RU-член кластера».

> **Вердикт: ставим, → RU-член своего кластера** (`/` для CV-пары, `/life/` для
> life-пары). x-default === hreflang ru URL → один физический URL носит две шляпы,
> нулевая поверхность дрейфа, одно тестируемое равенство. Согласовано с решением
> «корень = RU-дверь». Trade-off: искатель с не-ru/не-en локалью увидит RU — бакет
> мелкий, EN-рекрутёров уже матчит `hreflang="en"` напрямую. Если приоритет
> сместится — флип на EN = правка одного значения в головах + тесте.

**Конфликт 2 — hreflang в sitemap (`xhtml:link`).**
`test`: «i18n-практика, рекомендую». `architect`: «только head — второй источник
правды для кластера = дрейф».

> **Вердикт: head-only, sitemap плоский (только `<loc>`).** Механизмы Google
> не аддитивны (head ИЛИ sitemap), а дублирование = ровно тот класс дрейфа,
> который запрещает CLAUDE.md.

**Конфликт 3 — структура PAGES: хранить пары или вычислять.**
`architect`: поля `ru`/`en` в каждой записи. `test`: вычислять `altOf(url)`.

> **Вердикт: вычислять.** Меньше полей = меньше дрейфа; round-trip assert
> (`altOf(altOf(u)) === u`) страхует саму функцию.

**Конфликт 4 — nav-тест: как отличать вкладки от языка.**
`test`: новые `data-nav`-атрибуты. `architect`/`frontend`: дискриминатор уже есть.

> **Вердикт: разметку не трогаем.** Page-переключатель уже несёт
> `role="navigation"`, lang-группа — `role="group"` (shared.js:127,133). Скоупим
> парсинг теста по контейнеру. Правило CLAUDE.md про `data-*` — о динамических
> CSS-классах, не об этом.

**Конфликт 5 — updateMeta-парити на EN: nice-to-have или обязательно.**
`architect`: «nice-to-have». `test`: «единственная проверка JS/статика-синка на EN».

> **Вердикт: обязательно, по всем 4 страницам.** Google видит JS-рендер; если
> updateMeta на `/en/` разъедется со статикой головы — краулер и соц-бот увидят
> разное, и оба «работают». Ловится только этим тестом.

## 4. Решение

### 4.1 Два новых файла — копии своих RU-двойников

```
en/index.html       ← копия index.html       (префиксы src/ → ../src/, глубина 1)
en/life/index.html  ← копия life/index.html  (префиксы ../src/ → ../../src/, глубина 2)
```

Копировать строго со СВОЕГО двойника, не кросс: `life/index.html` тянет шрифт
Caveat, которого нет на CV-странице — кросс-копия молча потеряла бы шрифт.

Дельта каждой EN-головы от RU-оригинала:
- `<html lang="en">`;
- `title`, `meta description`, `og:title`, `og:description` — значения из
  `CONTENT.en` (title_cv/title_personal, hero.role + '. ' + hero.tagline —
  тест привяжет, руками не сочинять);
- `canonical` и `og:url` — свой URL (`https://artfaal.ru/en/`, `.../en/life/`);
- `og:locale` → `en_US`; добавить `og:locale:alternate` (на EN — `ru_RU`,
  на RU-страницах — `en_US`; статикой, updateMeta его не трогает);
- hreflang-блок кластера (см. 4.2);
- `og:type` наследуется от двойника (CV `profile`, life `website`) — не менять;
- скрипт-префиксы: в `en/life/index.html` все `../src/` → `../../src/`.

`meta name="author"` оставить как есть (кириллица не мешает, не og-поверхность).

### 4.2 hreflang-кластеры — взаимные, head-only

CV-пара — идентичный блок в `index.html` И `en/index.html`:
```html
<link rel="alternate" hreflang="ru" href="https://artfaal.ru/">
<link rel="alternate" hreflang="en" href="https://artfaal.ru/en/">
<link rel="alternate" hreflang="x-default" href="https://artfaal.ru/">
```
life-пара — идентичный блок в `life/index.html` И `en/life/index.html`:
```html
<link rel="alternate" hreflang="ru" href="https://artfaal.ru/life/">
<link rel="alternate" hreflang="en" href="https://artfaal.ru/en/life/">
<link rel="alternate" hreflang="x-default" href="https://artfaal.ru/life/">
```
Оба члена пары делят один блок → взаимность гарантирована конструкцией, тест
держит оба конца из одной таблицы. Все URL абсолютные, с trailing slash, строчными
(GH Pages регистрозависим, `/en`-без-слеша GH сам 301-ит на `/en/`).

### 4.3 shared.js — язык из URL

- `getLang()` (сейчас :71-73):
  ```js
  function getLang() { return /^\/en(\/|$)/.test(location.pathname) ? 'en' : 'ru'; }
  ```
  Якорь `(\/|$)` матчит `/en`, `/en/`, `/en/life/`, `/en/index.html` и не ложится
  на гипотетический `/energy/`. Никакого localStorage-фолбэка — остаточное чтение
  дало бы EN-тело на RU-URL под RU-canonical (дубль в индексе).
- `setLang()` (:74-77) — удалить целиком. Оставить определённой-но-мёртвой нельзя:
  dead-code-тест JS-функций упадёт (и это правильно).
- Новая функция — единственный владелец сетки URL:
  ```js
  function pageURL(page, lang) {
    return (lang === 'en' ? '/en/' : '/') + (page === 'personal' ? 'life/' : '');
  }
  ```
- `renderNav()` (:118-141) — все ссылки из `pageURL`:
  - бренд `tb-brand` (:122): `href="${pageURL('cv', lang)}"` — корень текущего языка;
  - вкладки страниц (:129,131): `pageURL('cv', lang)` / `pageURL('personal', lang)`
    — внутри EN ведут на EN; активной добавить `aria-current="page"`;
  - языковой переключатель (:135-137): `<button onclick>` → две `<a>` с
    `href="${pageURL(currentPage, 'ru'|'en')}"` и атрибутом `hreflang`;
    подсветка `is-on` по `_lang` как была; оба языка остаются ссылками
    (self-ссылка активного — не баг), активному `aria-current`;
  - PDF-кнопка (:139) — не трогать, `_lang` уже рулит суффиксом `_en`.
- `_lang` остаётся глобальным состоянием (правило CLAUDE.md), `initPage` как ставил
  из `getLang()`, так и ставит. JSON-LD/updateMeta правок не требуют — уже
  язык-зависимы через `CONTENT[lang]` и `location.pathname`.

### 4.4 sitemap — 4 `<loc>`

Добавить `https://artfaal.ru/en/` и `https://artfaal.ru/en/life/` (lastmod —
плейсхолдер, хук перепишет; changefreq/priority — копией стиля соседей). Без
`xhtml:link` (вердикт 2). Стаб `/cv/` и `404.html` в sitemap как не входили,
так и не входят.

### 4.5 test.js — таблица-объекты и инварианты

**PAGES (сейчас :249) → объекты; всё деривируется из таблицы:**
```js
const PAGES = {
  'index.html':         { url: '/',         lang: 'ru', page: 'cv'       },
  'life/index.html':    { url: '/life/',    lang: 'ru', page: 'personal' },
  'en/index.html':      { url: '/en/',      lang: 'en', page: 'cv'       },
  'en/life/index.html': { url: '/en/life/', lang: 'en', page: 'personal' },
};
const altOf = u => u.startsWith('/en') ? (u.slice(3) || '/') : '/en' + u;
```
Round-trip assert `altOf(altOf(u)) === u` на всех URL таблицы — работает уже на
двух записях (коммит 1). Assert «пара есть в таблице и зеркальна» (`lang`
противоположный, `page` тот же) — появляется в коммите 2 вместе с EN-записями.

**Call-sites смены типа значения** (строка → объект): sitemap-сверка (:369
`Object.values(PAGES).map(p => HOST + p.url)`), HTML-цикл (:318 `PAGES[file].url`).
`Object.keys(PAGES)` (requiredFiles :252, dead-code :626) переживают без правок —
и requiredFiles сам потребует существования `en/*` файлов.

**Per-page asserts в HTML-цикле** (замена хардкодов :309, :322, :328-329):
- `lang="${p.lang}"` вместо литерала `"ru"`;
- canonical === og:url === `HOST + p.url` (self; ловит cross-canonical);
- `hreflang="${p.lang}"` === self, `hreflang="${alt}"` === `HOST + altOf(p.url)`,
  `hreflang="x-default"` === RU-член пары — все три из таблицы;
- og:title/og:description === `CONTENT[p.lang]` (title по `p.page`);
- og:locale статикой === `p.lang === 'en' ? 'en_US' : 'ru_RU'` (сейчас не
  тестируется вообще) + og:locale:alternate === противоположный;
- og:type === (`p.page === 'cv' ? 'profile' : 'website'`) (сейчас не тестируется);
- шрифт-пары: строка Google Fonts у EN-головы === у RU-двойника (ловит потерю
  Caveat при копировании);
- og:image/og:site_name — как были, язык-нейтральны.

**Фикс слепого пятна cache-bust** (:339): `(?:\.\.\/)?` → `(?:\.\.\/)*` И в том же
цикле резолв каждого ref относительно директории файла + `fs.existsSync` — ловит
неверную глубину `../` (пустая страница при зелёном тесте — сейчас её не видит
никто).

**Nav-тест** (:398-416): в коммите 1 — только скоуп парсера вкладок контейнером
`role="navigation"` (существующие 2 состояния, поведение не меняется). В коммите 2,
когда язык становится `<a>` в `role="group"`: прогнать все 4 состояния (ru/en ×
cv/personal) — вкладки внутри EN ведут на `/en/`+`/en/life/`, href языкового
переключателя === `altOf(текущий url)` — та же истина, что hreflang. `_lang`
флипается через `vm.runInContext('_lang = "en"', sandbox)`.

**Unit-тест `getLang()`** — самый важный новый тест: все 8 форм путей
(`/`, `/index.html`, `/life/`, `/life/index.html` → ru; `/en/`, `/en/index.html`,
`/en/life/`, `/en/life/index.html` → en) + `/energy/` → ru. Плюс регрессия
«localStorage мёртв»: мок `localStorage.getItem → 'en'`, pathname `/` →
всё равно `'ru'`.

**updateMeta-прогон по всем 4** (:420-437, замена одиночного): для каждой записи
PAGES — `sandbox.location = { pathname: p.url }`, `_lang` флип, вызов
`updateMeta(CONTENT[p.lang], p.page)`, сверка og:title/og:locale/og:image со
статикой этой же головы. og:description НЕ сверять на CV: рантайм считает стаж
из дат, статика намеренно без стажа — расходятся by design.

**prompt_lines parity** (дополнение :48-49): у `CONTENT.en.hero.prompt_lines`
есть оба ключа `cv`/`personal`, массивы ≥ 2 — отсутствие ключа в EN сейчас =
краш страницы.

## 6. Что НЕ делаем

- **Cross-language canonical и `noindex`** на EN — убьют индексацию.
- **hreflang в sitemap** — второй источник правды (вердикт 2).
- **`/en/cv/`** — у EN не было URL-идентичности, нет legacy → нет стаба.
- **hreflang на стабе `/cv/`** — редирект, не контент.
- **Авто-редиректы/баннеры по `navigator.language`** — решение брейншторма.
- **Миграция localStorage / `removeItem('lang')`** — ключ просто мёртв, YAGNI.
- **robots.txt** — `Allow: /` уже покрывает `/en/`.
- **404.html** — RU-only, вне PAGES; EN-404 не заводим (не страница, экран ошибки).
- **generate-cv.js** — PDF строится из content.js, URL-структура его не касается.
- **Пререндер тел** — Google рендерит JS; ATS-слепота — известное ограничение
  (спека переезда §8.5), не этот scope.

## 7. Риски

1. **Битая взаимность hreflang / cross-canonical** → Google молча роняет EN.
   Невидимо в браузере. → Ловится только новыми asserts из таблицы.
2. **Неверная глубина `../` в en/life/** → страница пустая, тест сегодня зелёный.
   → existsSync-гард (4.5) + глазами Network-таб на `/en/life/`.
3. **Nav-тест поедет на `<a>`-переключателе** → скоуп по role-контейнерам,
   прогон 4 состояний.
4. **Старый visitor с `lang=en` в storage** увидит RU на `/` → by design, один
   клик до `/en/`; авто-honor вернул бы анти-паттерн. Регрессия-тест закрепляет.
5. **Забытая правка головы при копировании** (og:url, title) → все og/canonical/
   hreflang-поля под asserts из таблицы, руками ничего не сочиняется.
